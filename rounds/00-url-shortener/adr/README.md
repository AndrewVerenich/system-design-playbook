# ADR в этом раунде

**ADR (Architecture Decision Record)** — короткий файл про **одно** архитектурное решение.

Не заменяет [`DESIGN.sample.md`](../DESIGN.sample.md) (это design doc / RFC-стиль).  
ADR вырезает из него отдельные решения, чтобы их было легко найти и пересмотреть.

| ADR | Решение |
|-----|---------|
| [0001](./0001-redirect-status-302.md) | Redirect через **302**, не 301 |
| [0002](./0002-code-generation-snowflake-base62.md) | Код = **Snowflake → Base62** |

Типовая структура ADR:

1. **Context** — какая проблема и силы давления  
2. **Decision** — что выбрали  
3. **Consequences** — плюсы и минусы  
4. **Alternatives** — что отвергли и почему  

На интервью ADR вслух не зачитывают: говорят то же самое в секции trade-offs.  
В репо/работе ADR удобны для истории решений.
